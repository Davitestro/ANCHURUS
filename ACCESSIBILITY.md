# Accessibility Statement

## Our Commitment

ANCHURUS aims to make monocular depth estimation more accessible to developers, researchers, and users, regardless of their hardware capabilities or technical background.

Accessibility is an important consideration in how the project is developed, documented, and distributed.

We recognize that accessibility is not limited to user interfaces. It also includes computational requirements, documentation clarity, software compatibility, and the availability of understandable examples.

## 1. Hardware Accessibility

One of the main goals of ANCHURUS is to reduce the computational requirements traditionally associated with monocular depth estimation.

We aim to:

- Support inference on hardware with limited computational resources.
- Minimize unnecessary memory consumption.
- Keep model deployment requirements manageable.
- Provide CPU inference support where possible.
- Document hardware requirements and performance limitations.
- Avoid requiring expensive GPUs for basic model usage.

Performance and hardware compatibility may vary depending on the device, operating system, and software environment.

## 2. Documentation Accessibility

Project documentation should be understandable and easy to navigate.

We encourage contributors to:

- Use clear and descriptive headings.
- Explain technical terminology when necessary.
- Provide installation instructions with explicit commands.
- Include practical usage examples.
- Avoid unnecessary complexity in documentation.
- Keep documentation synchronized with the actual implementation.

## 3. Visual Accessibility

Depth estimation is a visual task, but its results should be presented in ways that are understandable to different users.

We encourage:

- Clear comparisons between input images and predicted depth maps.
- Sufficient contrast in visual demonstrations.
- Avoiding color as the only way to communicate important information.
- Providing textual descriptions for important visual examples.
- Using descriptive alternative text for images in documentation.

## 4. Software Accessibility

We aim to make ANCHURUS straightforward to install, configure, and use.

Where practical, the project should:

- Provide reproducible installation instructions.
- Minimize unnecessary dependencies.
- Avoid requiring specialized hardware.
- Handle invalid inputs gracefully.
- Provide understandable error messages.
- Document supported Python and PyTorch versions.

## 5. Compatibility

We recognize that users work with different operating systems, devices, and environments.

We aim to document compatibility with:

- Linux.
- Windows.
- CPU-based environments.
- CUDA-compatible GPUs.
- Common Python and PyTorch configurations.

Actual compatibility depends on the current implementation and available dependencies.

## 6. Contributions

We welcome accessibility improvements from the community.

Contributions may include:

- Improving documentation readability.
- Adding alternative text to images.
- Improving visualization contrast.
- Simplifying installation procedures.
- Reducing hardware requirements.
- Improving compatibility with different environments.

See [CONTRIBUTING.md](CONTRIBUTING.md) for contribution guidelines.

## 7. Feedback

If you encounter accessibility barriers while using ANCHURUS, we encourage you to report them through the GitHub Issues section.

Repository:

https://github.com/Davitestro/ANCHURUS

Please describe:

- The accessibility issue.
- The affected component or documentation page.
- Your operating system and environment, if relevant.
- Suggested improvements, if available.

We appreciate all feedback that helps make ANCHURUS more accessible.

## 8. Continuous Improvement

Accessibility is an ongoing process.

As ANCHURUS evolves, we aim to identify and address accessibility barriers across its documentation, software, visual demonstrations, and deployment requirements.

Our goal is to make lightweight monocular depth estimation easier to access, understand, and use.
